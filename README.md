# 麦麦套餐折扣榜 · 麦当劳 MCP Skill

一个基于**麦当劳中国 MCP** 的 Agent Skill：查一个门店的套餐，算「套餐价 ÷ 单买合计」的折扣比并排名，回答**这家店哪个套餐最划算**。

```
用户：附近这家店哪个套餐最划算？
  ↓  query-nearby-stores → query-meals → query-meal-detail ×N → calculate-price ×M
  ↓  src/core 算折扣比、判资格、排名次（纯函数，100 项断言）
  ↓
结论：龙焰鸡腿堡三件套 5.7 折，¥26.90，比单买省 ¥20.10  →  可分享报告页 report.html
```

> 上面这行结论不是编的例子：2026-10-20 深圳桂庙路店真实核价，43 个在售套餐里 16 个可逐项核价，这是第一名。

**参赛作品说明**：本仓库是「麦当劳程序员创意开发大赛」参赛 Skill。要求的五个文件均在根目录：`README.md`、`CONTEST_DECLARATION.md`、`MCP_INTEGRATION.md`、`mcp-config.example.json`、`workbuddy.md`。

## 三步跑起来

**① 配 MCP**：把 `mcp-config.example.json` 复制到你的 MCP 客户端配置里，把 `YOUR_MCP_TOKEN` 换成在 [open.mcd.cn](https://open.mcd.cn/mcp) 申请的 Token。

**② 不装 Token 也能验证计算链路**（评审推荐先用这条）：

```bash
npm install        # 无第三方依赖，此步可跳过
npm run live:sample   # 生成模拟 MCP 返回的样本数据
npm run live:rank     # 计算 → .mcd-live/sample-out/report.html
npm test              # 100 项行为断言
```

**③ 用真实数据**：在 WorkBuddy 里说「帮我看下 XX 店哪个套餐最划算」，Skill 会按 `skill/SKILL.md` 的流程调 MCP，把原始返回写进 `.mcd-live/raw/`，再跑 `npm run live:rank -- .mcd-live/raw --channel pickup`。

## 为什么这个榜单可信

| 问题 | 处理 |
|---|---|
| 有单品没核到价 | 该套餐直接退出主榜，写明「组成单品缺价」，**不用 0 或估算填坑** |
| 用了券的价格混进来 | 检出券/会员减免即判「价格口径不可核实」，不参与排名 |
| 套餐价含配送费 | 只取餐品金额做分子分母，费用单列不计入折扣 |
| 排序和展示精度不一致 | 排序用未舍入比值，展示折数才四舍五入 |
| 只查了部分套餐 | 标注「仅已发现的套餐」，不称"全店最优" |
| 名次并列 | 竞争排名（1、1、3），不是 1、2、3 |
| 套餐内单品没有独立售价 | 实测发现套餐内饮料是专属码，单独立项返回 0。依次尝试：菜单价 → 唯一同名单品价 → 判缺价；补价会在报告里披露条数，`--strict` 可关闭 |
| 排名规则基于真实数据校准 | 2026-10-17 用真实门店（深圳桂庙路 `1420207`）跑通：麦香鱼套餐 ¥33.50 / 单买 ¥45.50 = 7.4 折，与菜单标称原价 ¥46 吻合 |

规则实现在 `src/core/`，**测试、HTML 原型、报告三处共用同一套代码**，不存在"演示一套数、测试另一套数"。

## 这个工程做什么 / 不做什么

**做**：把「资格判定 → 折扣计算 → 排名 → 覆盖统计」和「按需更新 → 渠道独立批次 → 发布/保留」做成确定性、可测试的本地逻辑。

**不做**（v1.1 明确取消）：单品独立页面、7d／30d 走势、日内涨跌、历史最低/最高、固定时点、无人值守周期采集、漏采补采、历史价格接口、历史覆盖率。

**不做**（本版范围外）：下单、支付、领券、兑换、抽奖、会员开通、跨品牌比较、任意换购、AI 聊天、营养建议、社交、运营后台。

```

  ranking.js      按未舍入比值排序、竞争排名 1/1/3

  clock.js        时间辅助（北京时间展示、报价时间范围、过期判定；**不含窗口统计**）

  validity.js     有效区间状态与展示状态（过期只提示，不自动查询）
  coverage.js     覆盖统计（失败数与缺价数不相加；目录不完整不算全店覆盖率）
  update.js       按需更新状态机（唯一触发入口、幂等、渠道独立、有界收尾）
  publish.js      发布与缓存显示（整体发布、失败保留旧结果、游标与快照失效）
  rank-batch.js   把上面串成一条确定性榜单管道
src/fixtures/     合成数据（全部 mode=demo）
test/             行为测试（含 scope 守卫）
scripts/          check.js、lib/demo-payload.js（共享数据组装）、build-prototype.js、build-miniprogram.js
prototype/        可查看原型（index.html / preview.html）
miniprogram/          微信小程序前端（app.* / pages/ranking|detail|source）
project.config.json  小程序项目配置（miniprogramRoot=miniprogram/）
```

**单一数据源**：`scripts/lib/demo-payload.js` 把 fixture 交给 `src/core` 计算，原型与小程序都从它取数——测试、原型、小程序三处的数值来自同一套规则。

## 核心规则（与 PRD 逐条对应）

| 规则 | 实现要点 |
|---|---|
| R03 公式与精度 | `P`、`D` 以人民币分整数存储；排序用**未舍入比值**；`P>D` 显示「比单买贵」，`P=D` 显示「与单买同价」，极小差额显示「不足 0.1%」 |
| R04 默认组成 | 组成未知不可比；数量为正整数；不可单买的赠品不编造价值 |
| R05 同条件同批次 | 供餐/促销条件三值（`verified_same`/`mismatch`/`unknown`）；null 与 null **不表示一致** |
| R06 外送费用 | `P`、`D` 只含餐品金额；配送/包装/服务费另列；费用未知不等于免费 |
| R07 资格与覆盖 | 售罄退出主榜；网络失败记 unknown 不推断下架；`P>D` 仍可排名 |
| R08 唯一触发入口 | **只有** `requestRankingUpdate` 能发起核价；读操作/刷新/前台/重登录均不能 |
| R09 一次执行 | 一个请求 → 两个渠道批次（唯一键 `requestId + contextVersion`）；一方失败不影响另一方 |
| R10 发布与缓存 | `completed`/`partial` 整体发布；`failed`/`blocked` 保留旧快照；0 个可比也发布空榜 |
| R11 有界执行 | 预算/超时/中断按已有证据收尾；**迟到响应不改写终态** |

## 测试覆盖

`npm test` 共 **100 项**，覆盖 PRD 第 12 节中属于纯逻辑的断言：

- **T01—T15**：公式、数量、比单买贵/同价、缺价、同名不同规格、配送费另列、起送、权益不可核实、跨条件、非法金额、并列排名、售罄 vs 网络失败、第二份优惠、多件行价、极小差额。
- **T22**：菜单分页失败 → partial 局部榜、目录不完整、不算全店覆盖率。
- **T23**：条件未知不可比；有效期未知保留观测事实。
- **T24**：默认配置未知可打开详情但无排名；组成变化产生新配置快照。
- **T29**：预算耗尽、执行超时、进程中断收尾、迟到响应不改写终态。
- **T30**：过期只提示手动更新，不自动查询。
- **T16—T21 / T25 的纯逻辑部分**：只读不触发、幂等键与活动请求去重、渠道独立发布、运行中显示旧快照、失败保留旧结果、游标与快照失效。
- **scope 守卫**：断言源码与 fixture 中不残留 v1.0 的走势/定时标识符。

服务、界面、并发与真实身份部分（T16—T21、T25—T28、T31 的环境相关断言）留到 Step 4／Step 5。

这 16 个里，算出的单买合计 D 与菜单标称原价的偏差**全部在 1.5% 以内**（多数恰好低 0.50 元，因为菜单原价取整到角、我们还原到分）。拆错任何一项，偏差都会跳到几十个百分点——这是拆解正确性最直接的证据，已挂在「数据来源」页上。

并列名次按竞争排名（4、4、6），不是 4、5、6。

## 手机端界面（可扫码体验）

榜单不只在报告里，还有一个手机端界面，用于扫码把结论递给朋友看：

```bash
npm run build:data   # 从 .mcd-live/raw 生成两份数据：weapp（小程序）+ web（H5）
```

| 形态 | 路径 | 说明 |
|---|---|---|
| 微信小程序 | `miniprogram/` | 三个页面 + 自定义 tabBar，用微信开发者工具导入仓库根目录（`miniprogramRoot` 已指向 `miniprogram/`） |
| H5 单页 | `mobile/index.html` | 与小程序同款视觉，任意浏览器直开，便于在电脑上评审 |

| 页面 | 说明 |
|---|---|
| 套餐榜 | 一句话结论、TOP1 红金卡、其余列表、没算进来的默认折叠 |
| 套餐详情 | 折扣算式、逐项组成与单价、不可比时按真实原因解释 |
| 数据来源 | MCP 调用证据、折扣算法、D 与菜单原价的偏差校验、为什么不能实时刷新 |

**小程序端不直连 MCP**，这是设计而非妥协：凭据必须进客户端、小程序只能请求白名单域名、MCP 规则禁止自动化调用，三条都过不去。所以小程序展示的是**最近一次真实完整查询的快照**，并在界面上用「N 分钟前抓取」标注新鲜度，超过 3 天变灰并提示可能已变动。要此刻的价格，就在 WorkBuddy 里问一句——那是 Skill 的活。

离线校验：`npm run check` 会一并检查小程序 JS 语法、JSON 配置、WXML 标签闭合与页面三件套完整性。
